# 未登录计算机历史记录本地化设计

## 背景

Codex 桌面客户端的“计算机历史记录”由本机 Chronicle 服务负责采集、暂停、恢复、清除和查询。当前客户端同时把该功能绑定到账号级 Memories：设置页会先检查 Memories 是否可用，开启时会尝试启用 Memories；周期摘要进程还会通过 `codex exec` 强制使用 `openai-memgen`，并传入 `--ignore-user-config`。因此未登录时页面不可开启，摘要也不会使用用户在 `~/.codex/config.toml` 中配置的供应商和模型。

本功能要在不登录 ChatGPT 的情况下完整使用计算机历史记录，并让智能摘要与普通 Codex 对话复用同一套 API 配置。

## 目标

- 未登录时可以开启、暂停、恢复、清除和查询计算机历史记录。
- 原始活动记录和生成后的摘要只在本机持久化。
- 不检查、启用或写入 ChatGPT 云端 Memories。
- 自动摘要和历史问答使用 `~/.codex/config.toml` 当前生效的 `model`、`model_provider`、供应商地址、凭据和 `wire_api`。
- 当前配置为 Responses 协议时，摘要通过 Responses API 发出无状态请求。
- API 不可用时继续本地采集，不回退到 OpenAI 登录通道。
- 功能默认关闭，关闭时不改变上游客户端行为。

## 非目标

- 不改变 Chronicle 的采集内容、应用权限或隐私模式规则。
- 不实现新的云端同步、跨设备同步或历史导入导出。
- 不提供或安装本地大模型；用户可自行把当前供应商配置为本地兼容服务。
- 不修改普通 Codex 请求的供应商选择和协议行为。
- 首版只支持当前 macOS Codex 桌面客户端；其他平台保持关闭。

## 方案比较

### 方案一：复用 Chronicle，并提供本地 Memories 适配层（采用）

保留上游设置页、本机 Chronicle 服务、计算机历史插件和本地数据格式，仅替换 Memories 门槛与摘要供应商选择。该方案用户体验完整，改动集中，也能继续复用上游的暂停、清除和查询能力。

### 方案二：重新实现一套本地历史功能

自行实现采集服务、设置页、存储格式和查询工具，可以完全脱离上游，但重复代码多，维护和兼容成本高，不符合本次需求范围。

### 方案三：仅允许本地模型摘要

数据可以完全不离开机器，但要求用户额外运行兼容模型服务，也无法直接复用现有远程供应商。该限制不作为首版默认行为。

## 总体架构

功能由三个相互隔离的单元组成：

1. **设置与启动开关**：在 Codex++ 设置中增加默认关闭的“本地计算机历史记录”开关。只有 macOS 且当前客户端版本受支持时才允许启用。
2. **Chronicle 页面适配器**：仅修改计算机历史设置页的 Memories 可用性与开启流程，使其直接操作本机 Chronicle 服务，不伪造全局登录状态，也不影响正常 ChatGPT Memories 页面。
3. **摘要命令适配器**：对 Codex 桌面客户端启动的 CLI 增加透明包装。普通 CLI 调用原样转发；只有精确匹配 Chronicle `openai-memgen` 摘要调用特征时，才用当前有效配置中的模型与 provider 替换强制的 OpenAI provider。摘要任务继续与无关的用户指令、插件和工具配置隔离。

设置开关关闭、平台不支持或客户端版本不匹配时，三个单元都不生效。

## 组件设计

### 设置模型与管理界面

- 在 `BackendSettings` 和管理器前端设置中增加布尔开关，默认值为 `false`。
- 开关说明明确区分“本地持久化”和“远程模型处理”：历史文件与摘要文件只存本机，但远程供应商会收到生成摘要所需的活动文本。
- 只在 macOS 显示或允许开启；不支持的平台显示不可用状态。
- 设置变更沿用现有持久化和启动流程，不增加独立凭据或供应商配置。

### Chronicle 页面适配器

- 复用现有 `renderer-inject.js` 注入机制，但使用独立的版本签名和启用条件。
- 只在计算机历史设置模块中绕过 Memories 可用性检查。
- “开启”操作直接调用本机 Chronicle 配置与服务，不调用远程 Memories 查询、启用或写入 mutation。
- 暂停、恢复、清除和状态读取继续使用上游 Chronicle 服务接口。
- 不全局篡改账号状态、Memories 查询缓存或其他设置页面。
- 注入签名不匹配时停止适配并报告兼容性错误，不尝试模糊匹配。

### 摘要命令适配器

- 启动 Codex 桌面客户端时，为 `CODEX_CLI_PATH` 提供 Codex++ 管理的透明包装入口，并保存真实 bundled Codex CLI 的绝对路径，避免递归调用。
- 所有非 Chronicle 摘要调用都按原参数和环境直接执行真实 CLI。
- 只有同时满足下列特征时才认定为 Chronicle 摘要调用：
  - 子命令为 `exec`；
  - 参数包含 `model_provider="openai-memgen"`；
  - 参数包含 `X-OpenAI-Memgen-Request=true`；
  - 参数包含 Chronicle 使用的 ephemeral/read-only 约束。
- 对匹配调用移除：
  - `openai-memgen` 的 provider、认证、地址、WebSocket 和专用请求头覆盖；
  - 其他仅用于 OpenAI Memories 的配置覆盖。
- 通过 Codex++ 现有配置解析逻辑读取调用发生时的有效 `model`、`model_provider` 和对应 provider 配置，并为摘要调用生成最小化的执行覆盖；用户切换供应商后，下一次摘要自动生效。
- 保留 `--ignore-user-config`、`--ephemeral`、只读沙箱和 Chronicle 的功能禁用参数，避免后台摘要加载与模型连接无关的用户指令、插件或工具。
- provider 凭据不得写入命令行参数。已有 `env_key` 直接继承对应环境变量；直接 bearer token 或命令认证通过仅对子进程可见的环境注入或权限受限的最小化执行配置传递。
- 不设置备用 OpenAI provider，不读取 ChatGPT 登录令牌。

### Responses 请求约束

- 当前 provider 的 `wire_api` 为 `responses` 时，摘要使用 Responses API 请求格式。
- 请求必须是无状态调用：`store` 为 `false`，不发送 `previous_response_id`，不发送 `X-OpenAI-Memgen-Request`。
- 实现阶段先用假上游捕获真实 CLI 请求验证上述字段。如果当前 Codex CLI 已满足约束，保持直连；否则只为摘要调用增加本地转发层，在转发前强制修正请求体。
- 如果未来配置采用其他 Codex 支持的协议，遵循 Codex++ 现有协议适配，不在摘要功能内另写一套模型客户端。

## 数据流

1. 用户在 Codex++ 开启“本地计算机历史记录”，重新启动或重新加载 Codex 桌面客户端。
2. 页面适配器允许未登录用户直接启动本机 Chronicle 服务。
3. Chronicle 按上游规则采集允许的应用活动，并写入其本地存储。
4. 周期摘要触发时，摘要命令适配器识别 `openai-memgen` 调用，读取用户当前有效配置，并生成仅包含模型连接所需字段的执行覆盖。
5. Codex CLI 将本次摘要所需的活动文本发送给当前 API 供应商。
6. 模型返回摘要后，Chronicle 将结果写回本地历史目录。
7. 用户在聊天中询问历史时，计算机历史插件读取本地记录；普通 Codex 模型仍按当前配置组织最终回答。

远程供应商只接收完成当前摘要或问答所需的内容。Codex++ 不向 ChatGPT Memories 上传记录，也不创建云端 Memory。供应商自身是否保存请求日志不在客户端可强制控制的范围内。

## 本地存储与清理

- 沿用 Chronicle 管理的记录存储和 `~/.codex/memories/extensions/skysight/` 摘要输出，不复制到 Codex++ 自有数据库。
- 清除历史通过 Chronicle 服务接口执行，不手工递归删除目录。
- 清除操作只影响计算机历史记录，不删除普通 Codex 聊天、`config.toml`、认证信息或其他 memory 扩展。
- 日志不得写入活动正文、摘要正文、API Key、Authorization 头或完整请求体。

## 错误处理

- **API 不可用**：继续采集；摘要保留为待处理或失败状态，允许后续重试。
- **配置缺失**：提示当前 Codex API 配置不可用，不回退到 `openai-memgen`。
- **模型或协议不兼容**：保留本地记录并报告摘要错误，不影响暂停、恢复、清除和原始历史读取。
- **客户端版本不兼容**：禁用页面适配和摘要重写，显示需要更新 Codex++ 兼容规则。
- **包装器异常**：普通 CLI 调用必须继续透明转发；无法证明是 Chronicle 摘要调用时绝不改写参数。
- **Chronicle 服务不可用**：保持开关配置，但页面显示本地服务不可用，不触发任何云端替代流程。

## 测试设计

### 单元测试

- 设置默认值为关闭，并能正确序列化、反序列化。
- 摘要调用特征完整时才执行参数重写。
- 缺少任一识别特征时，参数和环境保持原样。
- 重写后不存在 `openai-memgen` 和专用请求头，同时保留 `--ignore-user-config` 与 ephemeral/read-only 约束。
- 重写后的参数、进程标题和日志中不出现 bearer token 或其他敏感 header 值。
- 真实 CLI 路径解析不会递归到包装器自身。

### 注入测试

- 未登录且开关开启时，计算机历史页可以调用本机开启、暂停、恢复和清除操作。
- 开关关闭时保持上游 Memories 门槛。
- 页面流程不会发起云端 Memories 查询或 mutation。
- 非计算机历史页面与全局账号状态不受影响。
- 未知资源签名失败关闭并显示兼容性错误。

### 假上游集成测试

- 使用本地假 Responses 服务和临时 `CODEX_HOME`，不读取真实凭据。
- 验证请求使用当前配置中的模型与 provider。
- 验证请求走 Responses 路径，`store=false`，且没有 `previous_response_id` 和 `X-OpenAI-Memgen-Request`。
- 验证 API 返回后摘要写入临时本地历史目录。
- 验证上游断开时采集状态不受影响，恢复后可以重试摘要。

### 回归与本机验收

- 现有启动器、renderer 注入和 bridge 测试继续通过。
- 普通对话、普通 `codex exec`、模型切换和供应商切换行为不变。
- 在退出 ChatGPT 登录的 macOS Codex 客户端中验证完整开启、暂停、恢复、清除和查询流程。
- 通过请求捕获确认云端 Memories 调用为零，并检查本地文件确实产生和清除。

## 验收标准

- 未登录用户可以完整操作计算机历史记录。
- 原始记录和摘要只在本机目录持久化。
- 所有智能处理复用 `~/.codex/config.toml` 当前生效的 API 配置。
- 不存在 `openai-memgen` 请求，不访问 ChatGPT Memories 接口，也不发生 OpenAI 登录回退。
- API 故障不阻断本地采集。
- 功能关闭或版本不兼容时，上游行为保持不变。

## 安全与发布边界

- 功能保持 opt-in，不自动为现有用户开启。
- 不修改 `Cargo.toml`、`package.json` 或依赖版本，除非实现阶段证明现有依赖无法满足需求并另行确认。
- 不提交真实历史记录、请求正文、供应商地址或凭据。
- 本设计不包含推送、发布或创建上游 PR。
